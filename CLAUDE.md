# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

**SOP Generator** interface — single-screen POC for creating a SOP from uploaded context documents and watching its generation progress.

Stack: Vite 8 + React 19 + TypeScript 6 + MUI 9 (Emotion) + TanStack Router 1. Package manager: **pnpm**.

Current state: POC. One SOP lives in React state at a time and nothing is persisted across a reload, but generation is **real** — a FastAPI host in `backend/` runs the pipeline from the sibling repo `../sop_generator` and streams its stdout to the UI over SSE.

**`../sop_generator` is read-only. Never modify it.**

## Commands

```bash
pnpm dev        # vite dev server (proxies /api -> 127.0.0.1:8000)
pnpm dev:api    # FastAPI host on :8000 — needed for generation to work
pnpm build      # tsc -b && vite build
pnpm preview    # serve the production build
pnpm lint       # eslint .        (read-only)
pnpm lint:fix   # eslint . --fix  (mutates files)
pnpm format     # prettier --write .
```

Both `pnpm dev` and `pnpm dev:api` must be running. There is no test framework. Do not
invent script names.

## Architecture

- `src/main.tsx` — root: `StrictMode` > `ThemeProvider` (`src/theme.ts`) > `CssBaseline` > `RouterProvider`.
- **Routing is TanStack Router file-based**: `src/routes/__root.tsx` (renders `Layout`) and `src/routes/index.tsx` (renders `SopGenerator`). There is no `App.tsx`. `src/routeTree.gen.ts` is generated by `@tanstack/router-plugin` (see `vite.config.ts`) — never hand-edit it.
- `src/components/Layout.tsx` — `TopNav` + `Container` + `<Outlet />`.
- `src/components/TopNav.tsx` — brand + `AppUserMenu`. No nav links (single screen).
- `src/pages/SopGenerator/SopGenerator.tsx` — the whole screen: empty state (inline centered card, **not** a drawer), header, tabs, progress, log, SOP output.
- `src/hooks/useSopGeneration.ts` — owns `sop` / `lines` / `progress`, `startGeneration(name, files)`, `reset()`. POSTs multipart to `/api/runs`, then consumes an `EventSource` on `/api/runs/{id}/events`.
- Components: `FileDropzone` (yields real `File[]`), `LogConsole` (streamed pipeline stdout), `StatusChip` (`generating` / `ready` / `failed`).
- `src/types.ts` — `SopStatus`, `LogLine`, `Sop`.

### Backend (`backend/`, Python 3.12 + uv)

- `app/main.py` — routes: `POST /api/runs`, `GET /api/runs/{id}`, `GET /api/runs/{id}/events` (SSE), `DELETE /api/runs/{id}`. No CORS — Vite proxies `/api`.
- `app/jobs.py` — in-memory job registry + runner. Calls `sop_pipeline.pipeline.run()` in a threadpool under `redirect_stdout`, forwarding each captured line to SSE subscribers.
- `app/config.py` — `SOP_GENERATOR_PATH`, `SCHEMA_GUIDE_PATH` (defaults to `<sop_generator>/sop_template_guide.md`), `OPENAI_API_KEY`. Validated at startup by `check()`.

Only route: `/`. Adding a page = add a file under `src/routes/`; the route tree regenerates on `pnpm dev` / `pnpm build`.

## Conventions

- Components: `export default function Name()`. Not arrow consts, no `React.FC`.
- Pages live in `src/pages/PascalCase/PascalCase.tsx`; shared components sit flat in `src/components/`.
- **Relative imports only** — no path aliases are configured (`vite.config.ts` has no `resolve.alias`, tsconfig has no `paths`).
- **Styling is MUI `sx` exclusively.** No `styled()`, no CSS modules, no Tailwind. Prefer theme tokens (`background.paper`, `text.secondary`, `primary.main`, `divider`, `action.selected`) over hex literals.
- Named imports from `@mui/material`; icons as default imports from `@mui/icons-material/Home` etc.
- Module-level `SCREAMING_SNAKE` constants declared above the component.
- Semicolons and single quotes in `src/**`. ESLint enforces `eol-last`.

TypeScript gotchas:
- `verbatimModuleSyntax` is on → type-only imports must use `import type`.
- `noUnusedLocals` / `noUnusedParameters` are on → unused variables break `pnpm build`.
- `strict` is **not** set → don't assume strict-null behavior.

## MUI MCP

`.cursor/mcp.json` registers a `mui-mcp` stdio server (`npx -y @mui/mcp@latest`).

Use it to look up MUI **v9** component APIs, props, and examples before writing MUI code rather than recalling from memory — v9 diverges from v5/v6 knowledge.

It is currently only wired up for Cursor. To use it from Claude Code, add the same stdio entry to a root `.mcp.json`.

## Known state / gotchas

- `@fontsource/roboto`, `@tanstack/react-query` and `react-hook-form` are installed but never imported.
- Theme is light mode in `src/theme.ts`: grey page bg, white hairline-bordered `Paper`, near-black `primary` (contained buttons), blue `info` for progress/running/links, green `success`.
- `@mui/icons-material` v9 has no bare `DeleteOutline` / `CheckCircleOutline` — use `DeleteOutlined` / `CheckCircleOutlined`.
- ESLint rule `react-hooks/set-state-in-effect` is an **error**: no `setState` in an effect body. `setState` inside an `EventSource` callback is fine.
- The pipeline exposes **no progress callback** — bare `print()` to stdout is the only signal, which is why the host captures stdout. `redirect_stdout` is process-global, so `backend/app/jobs.py` enforces **one run at a time** with a lock; `POST /api/runs` returns 409 when busy.
- The progress bar is derived by prefix-matching the pipeline's stage lines (`STAGE_MARKERS` in `useSopGeneration.ts`). If that wording drifts the bar stalls — the log stream is the real signal.
- `backend/pyproject.toml` pins `openai<3`: `sop_generator` declares `openai>=1.50.0` but its own lockfile uses 2.x, and a clean resolve otherwise picks up 3.x.
- The SOP tab renders markdown as preformatted text — **no markdown renderer is installed**.
- `docs/pipeline-integration-baseline.md` is the pre-integration audit. Its recommendations (Node host, shelling out to the CLI, nested step timeline) were **superseded**; its description of the pipeline is still accurate.
- `README.md` is the untouched Vite template — not a source of project info.
- Working branch is `feature/pipeline-integration`; PRs target `main`.
